# 04. 백엔드 및 API 명세

## 1. 구성
Vercel Node.js Serverless Function으로 `POST /api/analyze`를 제공한다. AI 및 DB 접근은 모두 서버에서만 수행한다.

## 2. API 계약
### 요청
`POST /api/analyze`

Header:
`Content-Type: application/json`

Body:
```json
{ "text": "오늘은 정말 즐거운 하루였다." }
```

### 성공 응답
HTTP 200:
```json
{
  "success": true,
  "data": {
    "sentiment": "positive",
    "confidence": 91,
    "reason": "즐거움과 만족을 직접 표현하는 긍정적 단어가 포함되어 있습니다."
  }
}
```
`createdAt`은 DB 저장 결과를 응답에 제공하기로 구현한 경우에만 포함한다. 저장 여부를 프론트엔드에 노출하지 않는다면 필드를 추가하지 않는다.

### 실패 응답
모든 오류는 동일한 구조를 사용한다.
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "분석할 문장을 1~2000자 사이로 입력해 주세요."
  }
}
```

## 3. HTTP 상태 코드
| 상태 | 코드 | 의미 |
|---|---|---|
| 200 | OK | 분석 성공 |
| 400 | VALIDATION_ERROR | 본문 누락, 잘못된 JSON, 빈 문자열, 길이 초과 |
| 405 | METHOD_NOT_ALLOWED | POST 이외의 메서드 |
| 429 | RATE_LIMITED | 요청 제한 초과 |
| 500 | INTERNAL_ERROR | 예상하지 못한 서버 오류 |
| 502 | AI_PROVIDER_ERROR | OpenAI 응답 실패 또는 형식 오류 |
| 503 | CONFIGURATION_ERROR | 필수 환경변수 누락 또는 서비스 설정 오류 |

오류 응답에는 API 키, 원본 스택, 내부 URL, DB 상세 정보가 포함되면 안 된다.

## 4. 서버 처리 순서
1. 요청 메서드 확인.
2. JSON 파싱 및 자료형 확인.
3. 문자열 trim 후 1~2000자 범위인지 검증.
4. 환경변수 존재 여부 확인.
5. IP 기반 또는 플랫폼 기능 기반 요청 제한을 적용한다. 신뢰할 수 없는 임의 헤더만으로 IP를 확정하지 않는다.
6. OpenAI API 호출.
7. 결과 스키마 및 값 검증.
8. Supabase에 결과 저장.
9. 성공 JSON 응답 반환.

DB 저장이 실패해도 AI 분석 결과가 정상이라면 분석 자체는 성공으로 처리한다. 이 경우 오류는 서버 로그에 안전하게 기록하되 사용자에게 저장이 성공했다고 거짓으로 안내하지 않는다. MVP 화면에 저장 상태를 노출하지 않는다면 저장 여부 문구를 만들지 않는다.

## 5. 입력 검증
- `text`는 문자열이어야 한다.
- trim 후 빈 문자열이면 거부한다.
- 최대 길이는 기본 2000자이며 `MAX_INPUT_CHARS` 환경변수로 조정할 수 있다.
- 환경변수 값이 숫자가 아니거나 유효하지 않으면 기본값으로 조용히 대체하지 말고 설정 오류를 기록한다.
- JSON 파싱 오류를 500으로 처리하지 않는다.

## 6. 보안 및 운영
- OpenAI API 키는 서버에서만 읽는다.
- Supabase Service Role Key는 서버에서만 읽는다.
- 사용자 입력을 로그에 남기지 않는다.
- CORS는 같은 출처 사용을 기본으로 하고, 별도 도메인이 필요한 경우 허용 origin을 명시적으로 설정한다.
- 요청 크기를 제한하고, 타임아웃 및 외부 API 오류를 처리한다.
- 사용자에게 내부 예외 메시지를 노출하지 않는다.
- 요청 제한은 운영 환경에 맞는 Vercel 호환 방식으로 구현한다. 별도 저장소 없이 서버 메모리에만 카운터를 두면 인스턴스 간 공유되지 않으므로 운영용 제한으로 간주하지 않는다.

## 7. 완료 기준
- 잘못된 메서드, JSON, 입력값에 명세된 오류가 반환된다.
- 정상 요청은 스키마가 검증된 결과만 반환한다.
- 비밀정보가 응답·브라우저 코드·로그에 노출되지 않는다.
- AI 오류와 DB 저장 오류가 서로 구분되어 처리된다.
